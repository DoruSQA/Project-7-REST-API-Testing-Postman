## 📄 Overview

**ShiftLeft-REST-API** is a Postman-based API automation project focused on testing an e-commerce REST API.

The collection covers three core API services:

* 👤 **User Service**
* 🏷️ **Product Service**
* 🛒 **Order Service**

In addition, the project contains dedicated **End-to-End workflows** that combine multiple services and validate complete business scenarios.

---

## ✨ Features

* 🛠️ **Full CRUD API Testing** — Coverage of Create, Read, Update and Delete operations across User, Product and Order services.
* ✅ **Positive Testing** — Validation of expected API behavior using valid request data and supported operations.
* ❌ **Negative Testing** — Validation of API error handling using invalid input, invalid IDs, unsupported values and non-existing resources.
* 🎯 **Edge & Boundary Testing** — Validation of boundary conditions such as empty values, maximum field lengths, zero quantities, negative prices and stock values.
* 🔍 **Input & Business Rule Validation** — Verification of API constraints such as valid email formats, supported roles/statuses, quantity rules and product stock behavior.
* 🧪 **Response Validation** — Automated assertions for HTTP status codes, response body content, returned values and expected API behavior.
* 📐 **JSON Schema Validation** — Validation of successful API responses against reusable JSON Schemas to verify response structure, required fields, data types and formats.
* 🔢 **Dynamic Test Data Generation** — Unique test data generated at runtime using JavaScript and timestamps.
* 🔗 **Request Chaining** — IDs and data generated by one request are stored in Postman variables and reused by subsequent requests.
* 🔄 **End-to-End Workflows** — Multi-step business scenarios combining User, Product and Order services.
* 📜 **JavaScript Test Scripts** — Custom pre-request and test scripts used for setup, data generation, variable management and assertions.
* ▶️ **Collection Runner Execution** — Support for executing individual test suites or the complete collection.
* 🌐 **Environment-Based Configuration** — API configuration managed through Postman environment and collection variables.

## 🔄 Test Data Management

One of the key characteristics of this collection is the use of **dynamic test data**.

Instead of relying exclusively on hard-coded entities, pre-request scripts generate unique values using timestamps.

Example:

```javascript
const timestamp = Date.now();

const userName = `JonnyCage_${timestamp}`;
const userEmail = `jcage_${timestamp}@gmail.com`;

pm.variables.set("USER_NAME", userName);
pm.variables.set("USER_EMAIL", userEmail);
```

This approach helps reduce conflicts caused by duplicate test data.

The collection also captures IDs returned by create operations and stores them in Postman variables.

For example:

```javascript
const body = pm.response.json();
const userID = body.data.id;

pm.collectionVariables.set("userID", userID);
```

These generated IDs can then be reused by subsequent requests.

This allows the collection to build request dependencies dynamically instead of relying entirely on pre-existing database records.
